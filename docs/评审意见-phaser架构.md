### 2. 明确"DOM UI + Phaser 演出"的混合策略（最重要的技术建议）

修仙游戏 90% 的界面是**列表/面板/文本流**（储物袋 40 格、灵兽资质面板、聊天流、剧情打字机）——Phaser 原生 UI 做这些的成本远高于 HTML/CSS。万界道友本身就是 React+DOM 的选择。

建议在 §3 增补一节：
- **Phaser 只负责**：战斗演出、地图画卷、特效、粒子；
- **HTML DOM 覆盖层负责**：一切面板/列表/文本（绝对定位盖在 canvas 上，与 EventBus 双向通信）；
- 场景键与导航流不变（§3.1 已预留"Phaser 偏演出层"的口子，把它定死）。

不提前定这条，后面每个面板都会在"用 Phaser 硬做还是偷偷写 DOM"之间摇摆，架构会腐化。

### 3. AiNarrativeService 必须注明"后端代理"方向

AI 生成的 API key 不能进前端；localStorage 单机存档与联网生成是**混合模式**。建议 §4.3/services 处注明：AI 接入必须走轻后端/云函数代理（key 服务端保管），前端只收结果——这影响部署形态，需在架构层面留句号。
