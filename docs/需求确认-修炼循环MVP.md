## 一、四项决定

| # | 决策点 | 决定 | 说明 |
|---|---|---|---|
| 1 | 闭关交互 | **状态式闭关** | 开启后持续修炼（在线/离线都涨修为），灵气或寿元耗尽自动停；竞品"动作式点按钮"的放置化改良 |
| 2 | 突破深度 | **完整版** | 三档火候 + 成功率公式明示 + 失败扣修为/感悟 + 连败 3 次生心魔 + 瓶颈期收益衰减 |

## 二、状态式闭关设计规格（对竞品的核心改良）

```
闭关（开关）
  开启 → 持续按速率产出修为（感悟低速同步累积）
       → 持续消耗：天地灵气（硬限速）+ 寿元（慢速）
       → 灵气耗尽：闭关自动暂停，灵气回复后可续（不自动重开，防无脑挂）
       → 寿元不足：闭关强制停止并强提示（以命换道的红线）
  关闭 → 随时切换去战斗/生产（闭关收益与战斗不可同时）
```

- **离线收益**：按离线时长结算（封顶 = 灵气池上限，天然防挂机溢出）；回归时弹"闭关回响"结算面板（AI 叙事，竞品"历练归来"模式）。
- **速率分层**：修为主产出、感悟低速副产出；具体数值全部进 `data/balance/` 配置表。
- 状态式与竞品"外出历练池"合并为同一离线管线，不做两套。

## 三、完整版突破框架（数值进配置表，结构如下）

- **三档火候**：强行（修为≥60%，风险最高）/ 常规（≥80%）/ 圆满（100% 且感悟≥50）；
- **成功率公式明示**（确认弹窗摊开）：`最终率 = 基础率 × 修为进度系数 × 感悟系数 + 命格机缘 - 心魔/丹毒惩罚`；
- **失败代价**：修为损耗、感悟降低；**连败 3 次生"心魔"状态**（持续减益，需特定方式化解——化解方式留扩展位，MVP 给简单解法如消耗道具/感悟冲刷）；
- **瓶颈期**：修为 ≥80% 后闭关收益衰减 50%，界面明示"瓶颈·建议外出历练"（软性逼战斗）；
- **小突破 vs 大突破**（竞品实测规律）：小境界突破（炼气内）不涨寿元上限、六维小幅成长；**大境界突破（→筑基）寿元上限大涨** + 解锁系统预告（筑基 = MVP 终点，解锁内容留二版本）。

## 四、四资源循环（MVP 经济骨架）

```
寿元 + 灵气 ──(状态式闭关)──▶ 修为 + 感悟 ──(赌突破)──▶ 境界/属性成长
   ▲                            │                          │
   │                        瓶颈衰减 ◀─80%+                │
   │                                                     ▼
   └── 大境界突破涨寿元上限 ◀──────────────────── 战斗/历练产出（灵石/材料→反哺）
```

- 灵气：随时间自动回复（上限随境界/设施成长）；寿元：单向消耗、大境界突破才涨上限——"以命换道"张力源头。

## 五、延后清单

| 延后项 | 原因 |
|---|---|
| 丹药增益闭关 / 丹毒系统 | 依赖炼丹玩法（后续版本） |
| 闭关事件（随机奇遇/心魔幻境） | 有趣但非骨架，后续加 |
| 转生/轮回（凡人"灵界重开"模式） | 长线版本 |

## 六、对架构的影响

1. `systems/cultivation/`：闭关从"动作"改"状态"——需要 `CultivationState`（开/关/暂停原因）进 `GameState`，离线结算在 `SaveManager` 读档时执行；
2. `RealmProgress.js`：承载修为条/感悟条/火候档位/心魔状态；突破公式读 `data/balance/breakthrough.json`；
3. 结算面板复用 `ResultOverlay`（闭关回响/突破回响同一套弹层配置）；
4. MVP 数值首版直接参照凡人境界寿元表（炼气百余岁/筑基 200+）。
